# LLM 원리

## 1. LLM 동작의 간단한 정리

- LLM은 다음 토큰 예측기이다. 앞의 토큰들을 보고 다음에 올 토큰의 확률 분포를 계산하고, 하나를 골라 붙이고, 이를 다시 반복한다. (자기회귀, autoregressive)
- 확률적으로 그럴듯한 답을 만들 뿐, 사실을 확인하는 장치가 기본적으로 내장되어 있지 않음. -> 할루시네이션의 근본 원인

## 2. 토큰

- 모델이 처리하는 텍스트 단위. 단어보다 작은 조각(subword)이며, BPE 같은 방식으로 나눈다.
- 영어는 대략 단어 1개 ≈ 1~1.5토큰 정도이고, 한국어는 같은 내용에 토큰이 비교적 더 많이 사용된다.
- 요금, 입력·출력 한도가 모두 토큰 단위로 계산된다.

## 3. 학습 단계

|#|단계|내용|결과|
|---|---|---|---|
|1|사전학습 (pre-training)|대규모 텍스트로 다음 토큰 예측 (자기지도학습)|언어와 지식을 익힌 "기반 모델"|
|2|지시 튜닝 (SFT, instruction tuning)|"질문 → 좋은 답" 예시로 추가 학습|지시를 따르는 모델|
|3|정렬 (RLHF 등)|사람이 고른 더 나은 답을 선호하도록 학습 (보상 모델 → 강화학습, 또는 DPO)|유용하고 안전한 응답|

- 지식 컷오프(knowledge cutoff): 사전학습에 쓰인 데이터가 수집된 마지막 시점. 모델은 해당 시점 이후의 사실은 모름. 추가적인 내용은 검색이나 RAG로 보완한다.

## 4. 컨텍스트 윈도우

- 모델이 한 번에 볼 수 있는 토큰 수. 입력과 출력을 합친 값임.
- 넘어선다면 앞부분이 잘리거나 처리하지 못한다.
- 컨텍스트 윈도우가 길다고 그 안에 넣은 내용을 모두 잘 활용하는 것은 아님. 긴 입력의 중간 내용을 놓치는 경향("lost in the middle")이 발생할 수 있으므로, 보통 중요한 지시는 앞이나 끝에 둔다.

## 5. 생성 제어(샘플링)

|파라미터|낮을 때|높을 때|언제|
|---|---|---|---|
|Temperature|확률 높은 토큰 위주 → 일관·결정적 (0에 가까우면 거의 항상 같은 답)|다양·창의적, 엉뚱한 답 증가|사실·코드·분석은 낮게, 아이디어·글쓰기는 높게|
|Top-p (nucleus)|누적 확률 p 안의 후보만 사용|후보가 넓어짐|temperature와 함께 다양성 조절|
|Top-k|후보가 적어 보수적|후보가 많아 다양해짐|—|

## 6. 임베딩

- 텍스트를 의미를 담은 숫자 벡터로 바꾼 것. 뜻이 비슷하면 벡터도 가깝다. (코사인 유사도로 측정)
- 의미 검색과 RAG의 기반이 됨.

## 참조: 기타 용어

|용어|의미|
|---|---|
|인컨텍스트 학습 (in-context learning)|가중치를 바꾸지 않고, 프롬프트 안의 예시만 보고 과제를 수행 (few-shot의 원리)|
|파라미터|모델의 가중치 개수 (예: 70B = 700억 개). 크면 일반적으로 성능↑, 비용↑|
|멀티모달|텍스트 외에 이미지·음성 등도 입력·출력|
|할루시네이션|그럴듯하지만 사실이 아닌 내용을 생성. 원인: 확률적 생성, 사실 확인 장치 없음, 학습 데이터 부족·컷오프|
