# LLM 활용

## 1. 프롬프트 기법

|기법|내용|사용 시기|
|---|---|---|
|Zero-shot|예시 없이 지시만|단순·일반적인 작업|
|Few-shot|입력→출력 예시 2~3개를 보여 줌 (인컨텍스트 학습)|형식이나 기준을 정확히 맞춰야 할 때 (분류 기준, 출력 모양)|
|역할 지정|"너는 ○○ 전문가다"|관점·용어 수준을 맞출 때|
|CoT (Chain-of-Thought)|"단계별로 생각해서 풀어라"|추론·계산·다단계 판단|
|출력 형식 지정|표, JSON, 항목 이름·개수까지 지정|채점 가능한 결과가 필요할 때|
|구분자|지시와 자료를 """, <자료>…</자료> 등으로 분리|긴 자료를 붙일 때 (지시와 자료가 섞이지 않게, 인젝션 방어에도 도움)|
|작업 분해 / 프롬프트 체이닝|큰 작업을 단계별 프롬프트로 나눠 앞 결과를 다음에 넘김|복잡한 과제|
|자기 검증 요청|"답한 뒤 조건 ①~⑤를 지켰는지 스스로 점검하라"|조건이 많은 과제|
|Self-consistency|같은 질문을 여러 번 풀게 해 다수결|정답이 하나인 추론 문제|

### 좋은 지시의 원칙
- 구체적으로 쓴다. 예) "짧게" -> "3문장 이내"
- 하지 말아야 할 것보다 할 것에 대해 작성한다. 예) "길게 쓰지 마" 대신 "100자 이내로 써"
- 중요한 지시는 앞이나 끝에 둔다.(lost in the middle)
- 불확실하면 "모름"이라고 답하게 허용한다.

## 2. 할루시네이션 대응


|방법|내용|
|---|---|
|근거 자료 제공 (grounding)|답할 근거를 프롬프트에 직접 넣고 "이 자료 안에서만 답하라"|
|근거 표시 요구|출처, 인용, 줄 번호를 함께 쓰게 함 → 검증이 쉬워짐|
|"모름" 허용|지어내는 대신 "확인 불가"를 쓰게 함|
|temperature 낮추기|사실 기반 작업|
|RAG|외부 문서를 검색해 근거로 넣어 줌|
|사람이 교차 검증|숫자는 직접 재계산, 사실은 원문 확인 → 최종 책임은 사람|

+ LLM은 계산·숫자 세기에 약하므로 계산은 코드로 실행하게 하거나 직접 검산한다.

## 3. RAG (Retrieval-Augmented Generation, 검색 증강 생성)

### 동작 순서
1. 문서를 작은 조각으로 나눔 (chunking)
2. 조각마다 임베딩(의미 벡터)을 만들어 vector DB에 저장
3. 질문이 오면 질문도 임베딩 -> 유사도가 높은 조각 상위 k개 검색
4. 검색된 조각을 프롬프트에 넣고 LLM이 답 생성

### 장점과 한계
|장점|한계|
|---|---|
|최신·사내 정보 반영 (컷오프 극복)|검색 품질에 좌우됨. 엉뚱한 조각을 찾으면 엉뚱한 답|
|출처 제시 가능 → 검증 쉬움|청크가 너무 크면 잡음↑, 너무 작으면 문맥이 끊김|
|할루시네이션 감소|검색 단계가 추가돼 지연·비용↑|
|모델 재학습 불필요|-|

### RAG vs 파인튜닝

||RAG|파인튜닝|
|---|---|---|
|바꾸는 것|모델에 주는 정보 (지식)|모델 가중치 (행동·말투·형식)|
|적합한 경우|자주 바뀌는 지식, 출처가 필요한 답|특정 형식·문체·전문 작업 방식|
|갱신|문서만 교체하면 됨|다시 학습해야 함|
|비용|상대적으로 쌈|학습 비용 큼 (LoRA로 줄임)|

## 4. 에이전트와 도구 사용

- 에이전트: LLM이 스스로 계획을 세우고, 도구를 호출하고, 결과를 보고 다음 행동을 정하는 반복 구조이다.
- ReAct 패턴: 생각(Reason) -> 행동(Act, 도구 호출) -> 관찰(Observe) -> 다시 생각 ==> 목표 달성 시까지 반복함.
- 도구 호출(function calling / tool use): LLM이 "이 함수를 이 인자로 호출해 달라"는 요청을 구조화된 형식으로 출력하고, 프로그램이 실행한 뒤 결과를 반환한다. 검색, 계산, 코드 실행, API 호출 등에 사용한다.
- MCP (Model Context Protocol): AI 앱이 외부 도구·데이터에 연결하는 표준 규격.
- 구성 요소: LLM + 도구 + 메모리 + 계획
- 멀티 에이전트: 역할을 나눈 여러 에이전트가 협업하는 형태

|위험|대응|
|---|---|
|앞 단계 오류가 누적|단계마다 중간 결과 검증|
|과도한 권한 (파일 삭제, 결제 등)|최소 권한, 중요한 행동 전 사람 승인(human-in-the-loop)|
|무한 반복·비용 폭주|반복 횟수·예산 제한|

## 5. 리스크·윤리·보안

|위험|내용|대응|
|---|---|---|
|기밀·개인정보 유출|외부 AI에 넣은 데이터가 저장되거나 학습에 쓰일 수 있음|사내 데이터·개인정보는 승인된 도구에만, 민감 정보는 가림(마스킹)|
|프롬프트 인젝션|입력 속 숨은 지시로 모델 동작을 조작. 직접(사용자가 입력) / 간접(웹페이지·문서 안에 숨긴 지시를 AI가 읽음)|지시와 데이터 분리(구분자), 외부 내용은 "데이터로만 취급", 도구 권한 최소화|
|탈옥 (jailbreak)|안전 장치를 우회하도록 유도|가드레일, 출력 필터|
|할루시네이션|그럴듯하지만 사실이 아닌 내용을 생성|근거 요구, 교차 검증|
|편향 (bias)|학습 데이터의 편향이 출력에 반영 (성별, 지역 등)|다양한 사례로 점검, 사람 검토|
|저작권|학습 데이터·생성물의 권리 문제|출처 확인, 사용 정책 준수|
|허위정보·딥페이크|그럴듯한 가짜 콘텐츠|출처 검증, 워터마크|
|자동화 편향 (과신)|AI 결과를 검토 없이 믿음|최종 판단과 책임은 사람|

## 6. 참조 용어

|용어|설명|
|---|---|
|시스템 프롬프트|대화 전체에 적용되는 기본 지시 (역할, 규칙)|
|가드레일|위험하거나 정책에 어긋나는 입력·출력을 막는 장치|
|LoRA|가중치 전체 대신 작은 추가 행렬만 학습하는 효율적 파인튜닝 (PEFT의 한 종류)|
|양자화|가중치를 낮은 비트(예: 32비트 → 8비트)로 표현해 모델을 작고 빠르게|
|지식 증류|큰 모델(교사)의 출력을 작은 모델(학생)이 따라 배우게 함|
|Diffusion 모델|노이즈를 단계적으로 제거하며 이미지를 생성 (Stable Diffusion 등)|
|GAN|생성자와 판별자가 경쟁하며 학습하는 생성 모델|
|벡터 DB|임베딩을 저장하고 유사도 검색을 빠르게 하는 DB|
|LLM-as-a-judge|LLM으로 다른 LLM의 출력을 평가. 편리하지만 편향이 있어 사람 검토와 함께 씀|
|SLM / 온디바이스 AI|작은 모델을 기기에서 직접 실행. 지연·비용·개인정보에 유리|
